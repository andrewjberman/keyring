# PART I — THE OUTCOME TERRITORY

Written as what a named kind of person can DO that they cannot do today. Each is qualitative and
disputable; no number is invented anywhere in this part. Step 2 cuts from here and nowhere else.

### O1 — A seat handed any pipeline tree answers "is this conformant, and against which rule" from one document

A seat — a worker, a COO lane, the CVO at L8 — is given a pipeline tree it has never seen. It opens
ONE document, the canon, and can say for each of the five axes (ingestion, bucket structure, naming,
compute, format) whether the tree conforms, departs, or is a declared exception — **and cite the
numbered rule** — without asking another seat and without reading a second document. Today that
answer requires Rule 17/17a/17b, four Andrew-direct records from 2026-09-12, a D10 PRD, an MDPF PRD
and a compliance clause in an ADVI PRD, and `1.0.0_SA_CTO` stated the failure this outcome ends:
*"a canon whose correct reading requires three other documents is not yet a canon"* (96216).

Every term the canon uses carries the PLANE it binds on — storage-path, entitlement, serving-route,
identity — so a rule about the storage-path segment `{scope}` cannot be scored against an entitlement
object's `scope_kind` (finding IV.7).

### O2 — Andrew ticks product-vs-firm for every scope in the estate from one table, in one sitting

Every scope the census found — enumerated by subtraction from the measured plane list, never from
recall — sits in one table with its evidence and the ruled default (`e29a895ce3` card 3: firm-shaped
where the served data is client-confidential, product-shaped otherwise). Andrew reads down one column
and ticks. That is the mechanism he approved for the residual of D10-1, and it converts a sovereign
call that has been open since 2026-08-25 — one nobody could answer in the abstract — into a single
read. The five scopes he has already named (`ANDREW_DIRECT_20260825_1755Z` — `opal-data-mdpf`,
`opal-data-etfs` product; `opal-data-49financial`, `-inflection`, `-cottonwood` firm) arrive
pre-ticked.

### O3 — A paused project's owner reads, row by row, what in their PRD the canon contradicts and what it does not — and resumes on that read

The owner of a project paused at ~16:1xZ opens a contradiction report for their project and sees,
per planned data structure, one of: CONFORMS · CONTRADICTS rule N (with the rule quoted) · OUT OF
PLANE (the canon does not govern this surface). The report is produced from the canon (O1) with a
plane-aware instrument — a storage-plane detector with a positive control that fires and a negative
control that does not (finding IV.7) — so it cannot manufacture the contradictions it exists to find.
An empty CONTRADICTS column is the project's lift evidence; a non-empty one is its amendment list.
Either ends that project's pause, which is Andrew's stated reason for pausing (*"we're going to come
up with a structure that could directly contradict them"*, `697a457a6d` scope clarification).

### O4 — Anyone naming a firm anywhere reads the name from one registry rather than spelling it

A seat writing a route, a bucket name, an IAM condition, a key prefix or a Terraform module needs a
firm's identifier. It reads it from ONE registry of firms, scopes and masters with stable keys, and
the artifact references that key. It does not choose a spelling. Today 49 Financial is `bd` to the
scoped router, `49financial` to Terraform, `49f` and `49financial` to the monolith (finding IV.4);
SmartX put entity UUIDs where a scope belongs and minted planes by the thousand (finding IV.3). Both
are the absence of this registry, not two separate mistakes.

### O5 — An engineer onboards firm N+1 by executing one checklist end to end and reaches a served dashboard with no one-off

Andrew: *"we're going to have the same pattern over and over again as we take on more and more
firms."* An engineer given a new firm follows one ordered checklist — mint the identity (O4), the
buckets, the IAM, the pipelines in the canonical grammar, the routes — and at the end a user of that
firm sees their dashboard. Nothing in the checklist requires a judgment call the canon has not
already made; anything that does is a defect in the canon, not a step in the onboarding. **This is
the outcome the other five exist to make possible.**

### O6 — Every plane in the estate carries a disposition someone can act on

Every tier plane the census measured carries exactly one of: CONFORMANT · MIGRATE (to where, under
which rule) · RETIRE · DECLARED EXCEPTION (the axis, the exact departure, why, who acknowledged it,
when, and whether it is permanent or conditional — the register schema `1.0.0_SA_CTO` specified in
`D10_GLOBAL_PIPELINE_STRUCTURE_PRD.md` §6). A seat picking up any migration project reads its rows
from here rather than re-censusing. The register's own failure mode is named in its schema: an
exception list that only grows is how the pattern dies, so every conditional entry can be audited for
an expired condition.
