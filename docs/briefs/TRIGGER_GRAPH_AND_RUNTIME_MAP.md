## 1. Measurement contract and honesty limits

- **Eastern time:** `ET` means `America/New_York`. EventBridge Rule cron is UTC, so each row prints both EDT and EST wall time. Scheduler rows respect each schedule's declared timezone; `America/New_York` schedules are DST-aware.
- **Rule invocation metric:** `AWS/Events Invocations`, `Sum`, exact 90-day window, dimension `RuleName`. This counts target invocations, not unique source events. A rule with two targets can record two invocations per match.
- **Rule failure metric:** `AWS/Events FailedInvocations` on the same window/dimension. Only three rules are non-zero; all three are 100% failed in-window.
- **Scheduler limitation:** AWS Scheduler exposes `InvocationAttemptCount` only at group level in this account. Group `default` recorded **287 attempts**, but no supported per-schedule dimension exists. Per-schedule trigger counts are therefore `N/O` (not observable), never allocated from the group total.
- **Resource activity:** Lambda `Invocations`, CodeBuild `Builds`, SQS `NumberOfMessagesSent`, SNS `NumberOfMessagesPublished`, Logs `IncomingLogEvents`, and CloudTrail `RunTask` are native resource/activity counts. They include all callers, so they are associated upper bounds, not attribution to one trigger.
- **Scope boundary:** the graph is exhaustive for immediate EventBridge/Scheduler targets. It does not recursively claim every downstream API call made inside a Lambda, SSM document, container, or build.
- **Business tagging:** target names are resolved first through `estate-coverage-resolver.json` and then through explicit current-name rules for post-snapshot resources. `Estate` is partner/business ownership; `Product` is the functional surface.
- **Runtime provenance:** P1 = repo-resident Lambda zip; P2 = S3-resident/pulled at runtime; P3 = image-resident; P4 = Lambda layer-resident dependencies. Transport targets receive `N/A`.

## 6. Highest-leverage work

1. **Repair and prove the two enabled failed controls first.** Fix the EventBridge-to-SNS authorization/configuration for `FIRMSEP-s3-direct-access-bypass` and `moltbot-ssm-sendcommand-alert`; replay one controlled matching event; require `FailedInvocations=0`, target-side receipt, and an alarm on any future failed invocation.
2. **Make the trigger map an executable, refreshable graph artifact.** Generate one canonical record per trigger-target edge containing service, expression/timezone, target ID/ARN, estate, product, provenance class, source identity, invocation metric, and failure metric. Gate the 4 missing Lambda source-map entries and the 8 duplicate same-resource edges in CI.
3. **Close Scheduler observability before the bulk migration.** Emit per-schedule success/failure counters from targets or a common wrapper, then migrate the 123 scheduled Rules in cohorts. Moving first would trade one standard violation for a per-schedule measurement blind spot.
4. **Pin graph runtime identity.** Replace the shared `:latest` task image reference with immutable tags or digests and record digest plus source commit in the task/runtime graph. This is the graph-infrastructure counterpart to the P2 artifact identity requirement.
